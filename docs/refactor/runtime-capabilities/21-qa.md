### RC-QA-009: Native log types and persisted records

Does every supported scalar/quantity LogData result type and the private capture
sequence preserve exact typed records in the configured application log?
The primary APP directly demonstrates text/realnumber; other current types use
documented property selection and established type encodings. Stage 6 implements
typed captures and static shape/order checks. Executor confirmation of derived
types, units, text encoding and persisted values remains open. Affects A09.
Evidence: [logging mapping](../../../autosuite/docs/22_LOGGING_MAPPING.md),
manual 3.7.11. Confirmation status: pending.

### RC-QA-010: Wall-time format boundaries

Does the deployed DateTime formatter preserve the selected directives and
Unicode/escaped literal text at calendar and local daylight-saving boundaries?
Stage 9 uses the observed F15 format and documented directive subset; reference
execution formats an explicit aware instant without host locale conversion.
No filename uniqueness or monotonic wall time is assumed. Affects A12. Evidence:
[wall-time mapping](../../../autosuite/docs/25_WALL_TIME_MAPPING.md), manual
3.11.1. Confirmation status: pending Executor verification, including year range.

### RC-QA-011: Native timer scope, reset and wait cancellation

Do repeated SetTimer tasks reset the same origin within one Macro and on later
Function invocations, and does `cancelwait=0` prevent early continuation on the
deployed Executor? Stage 10 gives Timer Function ownership in core/reference
execution; the AutoSuite profile accepts starts/resets in one lexical Macro
scope with waits there or in descendants. It does not hoist starts to make
branch-local timers visible. Waits leave equipment running until an explicit
stop. Only bounded literal durations compile while the fatal-check gate is open.
Affects A08. Evidence: primary APP and F13, manual 3.6.24 and 3.7.12,
[timing mapping](../../../autosuite/docs/26_TIMING_MAPPING.md). Reference schedules
and XML structure pass; scope/reset, cancellation and actual timing need Executor.
Confirmation status: pending platform verification; extends RC-QA-007.

### Stage-11 findings for RC-QA-002/003

The manual confirms expression evaluation and integer truncation, so native import
is not equivalent to SciLoom's strict literal conversion. Reference CSV now uses
an explicit UTF-8/comma/quoted profile and complete result commit. Fourteen native
measurement probes cover conversion, volume defaults, IO/EOF, mixed failures and
empty/multirow arrays. Their statuses remain pending; no portable target compiler
path bypasses this gate. See [CSV evidence](../../../autosuite/docs/27_CSV_READ_MAPPING.md).
In particular, determine whether a reliable literal/text ingress plus checked
per-column conversion is possible before proposing native implementation changes.

## Decisions already made

- Public CSV indexing is zero-based. Single-column reads still return tuples.
- Ordinary CSV failures stop; explicit defaults and try-forms permit bounded
  continuation. Logical records/units are portable; byte encoding is profiled.
- `at(device, zone)` captures a runtime selection and does not implicitly stop on
  exit. Selecting a new controller leaves an already-running previous one alone.
- JSON v4 grows additively. No migration is needed in this sequence; a genuinely
  incompatible future change requires its own explicit offline migration plan.
- Both packages enter 0.3.x, not 1.0.0. No release tag or PyPI publication.
