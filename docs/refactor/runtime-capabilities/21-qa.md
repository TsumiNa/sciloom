### RC-QA-009: Native log types and persisted records

Does every supported scalar/quantity LogData result type and the private capture
sequence preserve exact typed records in the configured application log?
The primary APP directly demonstrates text/realnumber; other current types use
documented property selection and established type encodings. Stage 6 implements
typed captures and static shape/order checks. Executor confirmation of derived
types, units, text encoding and persisted values remains open. Affects A09.
Evidence: [logging mapping](../../../autosuite/docs/22_LOGGING_MAPPING.md),
manual 3.7.11. Confirmation status: pending.

### RC-QA-010: Wall-time format boundaries

Does the deployed DateTime formatter preserve the selected directives and
Unicode/escaped literal text at calendar and local daylight-saving boundaries?
Stage 9 uses the observed F15 format and documented directive subset; reference
execution formats an explicit aware instant without host locale conversion.
No filename uniqueness or monotonic wall time is assumed. Affects A12. Evidence:
[wall-time mapping](../../../autosuite/docs/25_WALL_TIME_MAPPING.md), manual
3.11.1. Confirmation status: pending Executor verification, including year range.

### RC-QA-011: Native timer scope, reset and wait cancellation

Do repeated SetTimer tasks reset the same origin within one Macro and on later
Function invocations, and does `cancelwait=0` prevent early continuation on the
deployed Executor? Stage 10 gives Timer Function ownership in core/reference
execution; the AutoSuite profile accepts starts/resets in one lexical Macro
scope with waits there or in descendants. It does not hoist starts to make
branch-local timers visible. Waits leave equipment running until an explicit
stop. Only bounded literal durations compile while the fatal-check gate is open.
Affects A08. Evidence: primary APP and F13, manual 3.6.24 and 3.7.12,
[timing mapping](../../../autosuite/docs/26_TIMING_MAPPING.md). Reference schedules
and XML structure pass; scope/reset, cancellation and actual timing need Executor.
Confirmation status: pending platform verification; extends RC-QA-007.

### Stage-11 findings for RC-QA-002/003

The manual confirms expression evaluation and integer truncation, so native import
is not equivalent to SciLoom's strict literal conversion. Reference CSV now uses
an explicit UTF-8/comma/quoted profile and complete result commit. Fourteen native
measurement probes cover conversion, volume defaults, IO/EOF, mixed failures and
empty/multirow arrays. Their statuses remain pending; no portable target compiler
path bypasses this gate. See [CSV evidence](../../../autosuite/docs/27_CSV_READ_MAPPING.md).
In particular, determine whether a reliable literal/text ingress plus checked
per-column conversion is possible before proposing native implementation changes.

### RC-QA-012: Native CSV export mode and partial writes

Does exportbehaviour=0 select Append, and what exact bytes do the observed text,
delimiter and endline settings write? The manual's New File mode can overwrite;
F46's repeated logging is not proof of the enum label. Stage 12 implements
reference append with explicit UTF-8/comma/CRLF records and no rollback, while
AutoSuite rejects both forms. Six isolated probes measure sentinel retention,
repeated writes, Unicode/quotes/newlines and missing-parent errors. Determine
whether an error can leave a prefix and whether ordinary failure terminates the
caller. Affects A06; extends RC-QA-001/003. Evidence: F46, manual 3.7.9,
[append mapping](../../../autosuite/docs/28_CSV_APPEND_MAPPING.md). Status: pending
Executor and re-export evidence; no experimental semantics confirmation requested.

### RC-QA-013: Native Zone enumeration and display labels

Does native Zone addition retain first-occurrence order across overlapping Zones,
and do FindZone/WellFullName preserve the documented name and label behavior on
the intended deployment? Stage 13 preserves the primary APP's serialized index
order and resolves real well addresses through element ancestry. Reference values
use ordered uniqueness; static XML uses the manual's addition and named queries.
Single-well label compilation remains rejected until a reliable cardinality guard
exists. Test empty/duplicate unions, child-call copies, missing/case-variant names
and actual labels in Executor. Affects A03; evidence is
[the Zone mapping](../../../autosuite/docs/29_ZONE_VALUES_AND_LAYOUT.md).
Confirmation status: pending platform verification. This does not authorize
dynamic device binding by a display name.

### RC-QA-014: Sequential Zone capture and empty selection

Does the native macro retain the captured source and private current-fragment
Zone independently when a body/callee changes the semantic loop target? Does
the outer nonempty If prevent all sequential-macro effects for an empty source?
Stage 14 gives these behaviors precise reference semantics and emits isolated
source/iterator storage using F46's native profile. Verify repeated calls, nested
loops and target writes in Executor. Group divisibility and F43's error-handler
behavior also need the fatal-propagation gate before index/group compilation.
Affects A04; evidence: F43/F46, manual 3.8.10–12, and
[traversal mapping](../../../autosuite/docs/30_ZONE_TRAVERSAL_MAPPING.md).
Confirmation status: pending platform verification; no hardware result asserted.

### RC-QA-015: Native metadata defaults and same-value writes

Do the observed GetProperty fallback and SetProperty single-value profiles retain
text/Unicode exactly, including absent/incompatible properties and repeated or
nested calls? Does the explicit nonempty guard reliably skip empty writes? Stage
15 uses these manual-backed modes with argument capture and conservative local
single-well proof. Strict reads remain behind the failure-propagation gate.
Affects A07. Evidence: primary APP, F45/F46/F50, manual 3.7.6–7 and
[property mapping](../../../autosuite/docs/31_WELL_PROPERTY_MAPPING.md).
Confirmation status: pending Executor/re-export verification; reference execution
and static XML tests do not answer the platform question.

### RC-QA-016: Physical selection and native context transport

Can native dynamic Stir and cross-function Zone parameters preserve the captured
selection while reliably rejecting empty, outside-candidate and multi-controller
locations before any body action? Stage 16 validates real APP ancestry and gives
the scope explicit reference semantics. Logical configuration can be written
outside the scope; only physical commands require a selected candidate. Physical
snapshots retain A's applied configuration when the logical device switches to B.
No implicit stop/restore is inferred from F24. AutoSuite emission and private
context transport remain disabled until the fatal-propagation gate is verified.
Evidence: [selection mapping](../../../autosuite/docs/32_DYNAMIC_DEVICE_LOCATIONS.md),
F24 and manual 3.6.19. Confirmation status: pending Executor/re-export evidence.

## Decisions already made

- Public CSV indexing is zero-based. Single-column reads still return tuples.
- Ordinary CSV failures stop; explicit defaults and try-forms permit bounded
  continuation. Logical records/units are portable; byte encoding is profiled.
- `at(device, zone)` captures a runtime selection and does not implicitly stop on
  exit. Selecting a new controller leaves an already-running previous one alone.
- JSON v4 grows additively. No migration is needed in this sequence; a genuinely
  incompatible future change requires its own explicit offline migration plan.
- Both packages enter 0.3.x, not 1.0.0. No release tag or PyPI publication.
