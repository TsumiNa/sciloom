# Stage 10: Wait and timer

## Goal

Implement A08's monotonic duration semantics.

## Scope

Use [the authoritative contract](01-contract.md), not a separate API definition.
Declare Function-owned Timer resources, start/reset and wait_until; add ordinary wait. Extend the resource union without changing existing device fields. Perform definite-start analysis across branches/calls with no historical-entry assumption. Reference waiting advances a virtual clock; target maps observed waitmode 0/2 and SetTimer.

## Non-goals

No Timer sharing across Functions, contacts, physical setpoints, automatic stop or real sleeping.

## Implementation

The author API declares `timer: Timer` and uses `start()`, `wait_until(duration)`
or standalone `wait(duration)`. Schema checks keep timers separate from variables
and device slots, reject host access/sharing and preserve inherited roles. New
TimerResource records extend the existing resource field; StartTimer, Wait and
WaitUntil extend statements with fixed v4 kinds. No old record is renamed.

Shared compilation proves starts across branches, loops and calls without
assuming earlier entry invocations. Specialization prunes timers with unreachable
owning Functions. The interpreter uses an explicit VirtualClock, captures each
duration once, advances without sleeping and records immutable start/wait events.
Failed waits retain completed earlier effects and do not advance the clock.

AutoSuite emits SetTimer and Wait modes 0/2 using SI seconds and unique timer
names. Timer-only functions still receive an owning Macro. Current native scope
support requires starts/resets in one lexical scope and waits there or below;
broader Function-owned flow remains valid in core/reference execution. The target
rejects dynamic durations until fatal range checks are verified; literals must
fit the documented 0–79,999-hour range. `cancelwait=0` preserves elapsed waits,
using the documented option rather than the corpus's enabled-button default.
See [the mapping evidence](../../../autosuite/docs/26_TIMING_MAPPING.md) for
derived choices and outstanding Executor tests.

The author example `examples/timed_agitation.py` configures and starts a shaker,
waits two seconds, waits until five seconds from its timer start, then stops.
The developer example `examples/developer/timing_ir.py` constructs the same
five-second timing sequence as direct IR and round-trips JSON. Both companion
files are generated by their examples and included in the public download list.
